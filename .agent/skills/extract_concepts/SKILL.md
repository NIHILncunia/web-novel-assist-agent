# 기능: 외부 컨셉 추출 (Concept Extraction from External Entity)

> **작성일:** 2026-01-14
> **수정일:** 2026-01-20 (국가/지역/단체 포함 및 파일명 규칙 지정)

## 1. 개요
이 문서는 외부의 유명 작품(소설, 게임, 영화 등)에 등장하는 **캐릭터, 사물, 아티팩트, 국가, 지역 등(이하 엔티티)**을 분석하여, 그 핵심 컨셉(키워드)을 추출하고, 이를 통해 마스터의 세계관 데이터베이스(`data/traits/`, `data/ability/`)를 풍부하게 만들 범용 '트레잇'과 '어빌리티'을 생성하기 위한 지침입니다.

**핵심 목표:** 특정 엔티티의 설정을 그대로 베끼는 것이 아니라, 분석을 통해 얻은 아이디어를 재사용 가능한 데이터로 변환하여 데이터베이스를 확장하는 것입니다. **이 데이터는 몬스터, 캐릭터, 아이템 구분 없이 사용되는 공용 자산이 됩니다.**

**⚠️ 기준 참고:** 트레잇(Trait)과 어빌리티(Skill)의 구분이 모호할 경우, **`prompt/01_creation/create_trait.md`의 '1. 트레잇 vs 어빌리티 구분 기준'**을 반드시 참조하여 올바르게 분류하십시오.

**⚠️ 중요:** 트레잇/어빌리티 생성 시 반드시 `manuals/97_trait_and_naming_rules.md`의 규칙(모듈화, 이중 수식 금지 등)을 준수하십시오.

## 2. 작업 프로세스

### 1단계: 엔티티 분석 및 키워드 추출
1.  사용자로부터 분석할 대상(캐릭터, 사물, 국가 등)의 이름과 출전 작품을 입력받습니다. (예: `아서스 메네실, 워크래프트` 또는 `발할라, 북유럽 신화`)
2.  해당 대상의 서사, 기능, 성격, 어빌리티, 상징성 등을 종합적으로 분석하여, 그 정체성을 대표하는 **핵심 키워드를 최소 5개 추출**합니다.

### 2단계: 키워드별 데이터 생성 및 확장
1.  **직접 추출 (Extraction):** 각 키워드와 직접적으로 연관된 트레잇이나 어빌리티를 **반드시 3개** 생성합니다.
2.  **참조 지침 준수:** 어빌리티 생성 시, 다음 파일의 속성 정의(대상, 피해 유형, 상태 이상 등)를 반드시 확인하고 포함해야 합니다.
    *   **지속 어빌리티:** `prompt/01_creation/create_passive_skill.md`
    *   **발동 어빌리티:** `prompt/01_creation/create_active_skill.md`
3.  **브레인스토밍 (Expansion):** `prompt/02_refinement/brainstorm_from_keyword.md`의 로직을 활용하여, 파생되거나 비틀어진 아이디어를 **반드시 5개** 확장합니다.
4.  **구조적 생성 (Structured Generation):** 어빌리티 생성 시, **`manuals/99-1_ability_syntax.md` (모듈형 어빌리티 구조)**를 참조하여 **[권역:원천]-[계통]-[형태]**에 기반한 체계적인 어빌리티를 제안하십시오.
5.  **수량 준수:** 키워드 하나당 **총 8개(3+5)**의 아이디어가 도출되어야 합니다.
6.  **다양성 확보:** 트레잇(Traits), 지속 어빌리티(Passive), 발동 어빌리티(Active)이 골고루 포함되도록 합니다.

> **⚠️ 트레잇 vs 어빌리티 구분 기준:**
> *   **어빌리티 (Skill):** 자신이나 아군에게 이로움을 주거나(버프), 적에게 해로움을 주는(너프/피해) **기능적 유용성**이 있어야 합니다.
> *   **분류 주의:** 자신에게 **불리한 효과(Self-nerf)**만 있거나, 단순한 신체적/정신적 상태는 **어빌리티가 아닌 '트레잇(Trait)'**으로 분류하십시오. (예: '생존자의 죄책감' -> 트레잇)
>
> **데이터 필드 정의:**
> *   **기본 형식:**
>     *   **헤더:** `* **[태그] 한글 이름 (영문 이름)**` 형식을 사용합니다. (태그: `[트레잇]`, `[발동]`, `[지속]`)
>     *   **속성:** 하위 항목으로 들여쓰기하여 작성합니다.
> *   **이름:** 재사용 가능한 범용적인 이름을 사용합니다. (예: `[발동] 화염구 (Fireball)`)
> *   **제안 사유:** 해당 캐릭터의 어떤 특징에서 이 아이디어를 착안했는지 설명합니다. **(원작의 고유명사, 영문명 등 자유롭게 사용 가능)**
> *   **설명:** 데이터베이스에 실제로 들어갈 설명입니다. **특정 캐릭터의 이름이나 저작권이 있는 고유 명사를 절대 배제하고**, 범용적으로 작성해야 합니다.

### 3단계: 데이터베이스화 제안
1.  각 키워드로부터 생성된 모든 아이디어('기존 연관 항목' 및 '신규 제안 항목')를 키워드별로 그룹화하여 정리합니다.
2.  각 아이디어를 마스터의 데이터베이스에 바로 추가할 수 있도록, 아래의 **'데이터 제안 형식'**에 맞춰 가공합니다.

### 4단계: 자가 점검 (Self-Verification) - 필수
리포트 작성 완료 후, 반드시 다음 절차를 수행하여 중복을 확인합니다:

1. **기존 데이터 로드:**
   - `data/traits/` 폴더의 모든 `.md` 파일을 읽어 기존 트레잇 데이터를 확인합니다.
   - `data/ability/발동.md` 및 `data/ability/지속.md` 파일을 읽어 기존 어빌리티 데이터를 확인합니다.

2. **중복 검사 수행:**
   - 리포트에서 생성한 모든 트레잇/어빌리티의 **이름**을 기존 데이터와 비교합니다.
   - 이름이 정확히 일치하는 경우 → 중복으로 판단
   - 이름은 다르지만 **설명의 핵심 내용이 거의 동일한 경우** → 중복으로 판단
     * 예: "무기를 복제한다" vs "무기를 재현한다" → 유사도 높음, 중복 가능
     * 예: "화염 공격" vs "불꽃 공격" → 유사도 높음, 중복 가능

3. **중복 표기 추가:**
   - 중복이 발견된 항목은 해당 항목의 **이름 옆에** `(이미 존재)` 괄호 표기를 추가합니다.
   - 예시:
     * `*   **[트레잇] 불사의 육체 (Immortal Body)** (이미 존재)`
     * `*   **[발동] 화염구 (Fireball)** (이미 존재)`

4. **최종 리포트 수정:**
   - 중복 표기가 추가된 리포트를 최종 버전으로 저장합니다.
   - 사용자에게 전달할 때 중복 항목이 표시되어 있음을 명시합니다.

**⚠️ 중요:** 중복 표기가 된 항목은 데이터 적용 시(`/apply-report-data` 워크플로우) 자동으로 제외되며, 기존 데이터에 추가되지 않습니다.

    *   **설명:** 내면의 사악한 기운이 육체에 영향을 미쳐, 피부가 창백해지거나 신체 일부가 기괴하게 변형됨.

#### [신규 지속 어빌리티 제안]

    *   **제안 사유:** 죽음의 기사가 뿜어내는 공포와 죽음의 냉기를 형상화.
    *   **설명:** 주변 생물의 활력을 미약하게 저하시키고, 살아있는 존재에게 본능적인 불쾌감과 공포를 지속적으로 유발함.

    *   **분류:** `data/ability/발동.md`
    *   **계통:** 특수(흑마법)
    *   **대상:** 단일

## 4. 데이터 저장 및 파일명 규칙
1.  **저장 위치 및 파일명:** 생성되는 분석 리포트는 반드시 **`report/concept_analyze/`** 폴더에 저장하며, 파일명은 **`[작품명]_[엔티티명].md`** 형식을 따릅니다.
    *   예: `fate_zero_iskandar.md`, `warcraft_arthas.md`, `marvel_wakanda.md`
2.  사용자의 선택을 받은 신규 아이디어는, 제안된 분류에 따라 각 데이터베이스 파일(`data/traits/` 또는 `data/ability/`)에 추가되어야 합니다.
