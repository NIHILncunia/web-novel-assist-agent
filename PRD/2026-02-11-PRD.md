# Product Requirements Document (PRD)

## 1. Project Overview
* **Project Name**: NOVEL (노블): 웹소설 창작 보조 에이전트
* **bkit Level**: **Dynamic (Agentic)**
    * *Note: Python 기반의 복합 에이전트 시스템으로, 정적 웹이 아닌 동적 데이터 처리를 수행함.*
* **Goal**: 웹소설 작가의 창작 과정을 11단계로 체계화하여 설정 오류 방지, 완급 조절 최적화, 집필 속도 향상을 지원하는 AI 에이전트 시스템 구축.
* **Target User**:
    * 체계적인 설정을 원하는 웹소설 작가
    * 설정 구멍이나 스토리 막힘으로 고생하는 지망생
    * 다작을 관리해야 하는 전업 작가
* **Key Value**:
    * **Zero Setting Conflicts**: 템플릿 기반 설정 관리로 모순 방지.
    * **Structured Workflow**: 11단계 프로세스로 기획부터 퇴고까지 가이드.
    * **Reusable Assets**: 세계관, 캐릭터 등을 모듈화하여 재사용 가능.

## 2. Tech Stack & Environment
* **Language**: Python 3.12+ (Type Hinting Required)
* **Package Manager**: `uv` (Universal Python Packaging)
* **Core Dependencies**:
    * `pdfplumber`: PDF 자료 처리
    * `langchain` (Expected): AI 에이전트 로직 (추후 확장 시)
* **Interface**:
    * CLI / Terminal-based Interactive Agent
    * Markdown File System (Database)
* **Infrastructure**:
    * Local Filesystem (Primary Storage)
    * Git (Version Control)

## 3. Core Features & User Flow
### 3.1. User Flow
1. **Init**: `START_HERE.md` 프롬프트를 통해 프로젝트 시작.
2. **Incubate**: 아이디어 발상 및 초기 설정 (`incubator/`).
3. **Promote**: 작품명 확정 후 정식 프로젝트로 승격 (`projects/`).
4. **Execute**: 11단계 프로세스에 따라 기획 -> 집필 -> 퇴고 반복.

### 3.2. Detailed Features
* **Workflow Engine**: 
    - Step 0~10까지의 순차적 진행 가이드.
    - 각 단계별 산출물(Artifact) 자동 생성 및 검증.
* **Knowledge Management (Bible)**:
    - `00_bible/` 폴더 내 세계관, 캐릭터, 아이템 등 설정 데이터 관리.
    - Markdown 템플릿을 통한 일관성 유지.
* **Context Awareness**:
    - `00_conversation_log.md`를 통한 대화 맥락 유지.
    - `manuals/` 참조를 통한 규칙 준수.

## 4. Data Structure (Markdown Schema)
* **Incubator/Project Root**:
    * `00_bible/`: 설정 데이터 (YAML Frontmatter + Markdown)
    * `01_planning/`: 기획 문서 (Logline, Synopsis, Plot)
    * `02_drafts/`: 본문 원고
* **Naming**:
    * Directories: `kebab-case` (e.g., `shared-world`)
    * Files: `snake_case` or `kebab-case` typically, but adhere to manual specifics.

## 5. Non-Functional Requirements & Risks
* **Consistency**: AI의 응답이 `manuals/`의 규칙을 엄격히 따라야 함.
* **Preservation**: 사용자의 작성 내용은 절대 유실되어서는 안 됨.
* **Risks**:
    * 긴 대화 로그로 인한 Context Window 초과 문제 -> 요약 기능 필요.
    * 파일명/폴더 구조 임의 변경 시 에이전트 인식 불가 리스크.
