# [Common] 대화 로그 기록 지침 (Logging Guidelines)

> **파일명:** `manuals/99_common_logger.md`
> **목적:** AI와 사용자 간의 상호작용 및 작업 내역을 체계적으로 기록하여, 프로젝트의 맥락(Context)을 유지하고 에이전트가 기억을 잃어버리는 현상을 방지함.

---

## 1. 로그 파일 정책

### 1-1. 파일 생성 시점
*   **Step 0 (아이디어 발상) 혹은 Step 1 시작 직후,** 프로젝트 폴더(incubator 또는 projects)가 생성되는 즉시 `00_conversation_log.md` 파일을 생성해야 합니다.
*   만약 인큐베이터 폴더 생성 전이라면, 메모리에 기록해두었다가 폴더 생성 시점에 일괄 기록합니다.

### 1-2. 파일 위치
*   **초기 단계:** `incubator/[가제_컨셉명]/00_conversation_log.md`
*   **확정 단계:** `projects/[작품명]/00_conversation_log.md`

---

## 2. 기록 원칙 (Logging Rules)

1.  **실시간성:** 중요한 사용자 결정(Choice)이나 파일 생성 작업(Action) 직후에 로그를 업데이트합니다.
2.  **요약(Summary):** 대화 내용을 그대로 복사하지 말고, 핵심 내용 위주로 요약하여 문조체(개조식)로 기록합니다.
3.  **한국어:** 로그는 반드시 한국어로 작성합니다.
4.  **섹션 구분:** 날짜와 작업 단계(Step)로 섹션을 구분하여 가독성을 높입니다.

---

## 3. 기록 포맷 (Template)

로그는 '블록(Block)' 단위로 기록하며, 각 블록은 하나의 완결된 상호작용(턴)을 의미합니다.

```markdown
# [프로젝트명] 대화 로그

## [Step N] 단계명 (예: [Step 0] 아이디어 발상)

### 블록 1
---
=> **User Request:**
```
(사용자의 요청 **전문**. 절대 축약하지 말고 있는 그대로 복사해서 붙여넣을 것.)
```

=> **Agent Action:**
(에이전트의 처리 사항, 답변, 파일 생성 내역)
---

### 블록 2
---
=> **User Request:**
...

=> **Agent Action:**
...
---
```

## 4. 작성 예시

### 블록 1
---
=> **User Request:**
선호 장르는 판타지. 주인공은 용병으로 시작해서 기사왕이 되는 이야기.

=> **Agent Action:**
1. 사용자 요구사항 분석 및 3가지 컨셉(왕도, 패도, 경영) 제안.
2. `task.md` 업데이트.
---

---

## 5. 에이전트 행동 수칙
*   작업을 시작하기 전, `00_conversation_log.md`를 읽어 이전 맥락을 파악하십시오.
*   작업을 마친 후, 반드시 로그를 업데이트하십시오.
*   사용자가 "기억나?"라고 물어보면 이 파일을 최우선으로 참조하십시오.
